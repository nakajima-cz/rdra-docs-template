# ADR-0002: 要件定義に RDRA を採用

- ステータス: Accepted
- 日付: YYYY-MM-DD

## コンテキスト
要件の抜け漏れ・不整合を防ぎ、要件→設計→実装のトレーサビリティを確保したい。

## 決定
要件定義は RDRA 2.0（4レイヤー）で行い、成果物を `docs/rdra/` に配置する。

## 理由
- 要素の「つながり」で網羅性・整合性を担保できる
- 画面一覧・UC が下流の specs と 1対1 で対応づけやすい

## 影響
- `rdra/` のディレクトリを4レイヤーに対応させる
- 画面/API 設計書は RDRA の画面・UC を起点に作る
