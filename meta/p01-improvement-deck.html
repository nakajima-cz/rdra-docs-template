改善 ① — 最も深刻だった穴

ブリーフの転記漏れが UC を丸ごと消す

原因

要望の原典からブリーフへ転記する際に「利用者はWebで蔵書を確認できる」が抜けた。 構造は完全に整合するので整合チェッカには映らない。 ブリーフ作成は人の作業だから検証不要、という前提が穴だった。

対処

着手前チェックを新設。ブリーフ8節に転記元資料を挙げさせ、 Step1 の前に「資料にあってブリーフに無い要素」を洗い出させる。 見つけたものは [転記漏れの疑い] で未決へ出し、 人がブリーフを直すまで成果物に書かせない。

効果

2周目以降、毎周 4〜5件を安定して検出。 6周目では実行者が「蔵書検索を UC に起こしかけたが、この一文で止まった」と報告。

一般化：唯一の入力が壊れていれば後工程は全部壊れる。 機械検査で原理的に検出できない欠陥には、人の作業にも完了条件を置くしかない。

改善 ①5 / 10
改善 ② — 静かに成立する嘘

同じ ID が別の名前を指しても ERROR 0 だった

原因

整合チェッカが ID の存在しか見ていなかった。 対応表の UC-001 認証する と定義側の UC-001 会員を登録する が 正面から矛盾しているのに ERROR 0。採番し直した瞬間に嘘の対応表が静かに成立する。

対処

ID↔名称の整合チェックを実装。 さらに誤爆を防ぐため、名称の定義元とみなすのは 「1列目が ID 列、2列目が名称列」の表だけに限定（ヘッダ行を解析して判定）。 地の文と補助表は対象外。

効果

4観点で実測確認 —— 真の不一致は検出、補助表は誤爆なし、 人工的な不一致も検出、両 copier 構成の新規展開で ERROR 0。

副作用も実測した：最初の実装は補助表の2列目を名称と誤認し、 一度に ERROR 12件を誤爆した。チェックを足したら必ず誤検出側も試す。

改善 ②6 / 10
改善 ③ — 出口のない袋小路

雛形サンプルの ID が実案件の採番と衝突した

原因

雛形が UC-001 SCR-001 をサンプルとして出荷していた。 案件が UC-001 を実内容で採番した瞬間に対応表のサンプル行と衝突し、 触っても触らなくても ERROR。P01 の範囲で ERROR 0 にできる書き方が存在しなくなった。

対処

雛形サンプルの ID を予約帯の 900番台へ移動。 あわせて「900番台は全判定項目の母集団から除外し、例示行の削除対象にも含めない」と明記。

効果

実案件は 001 から自由に採番できるようになり、 6周目は対応表・個票を一切触らずに ERROR 0 で完了。

一般化：「残せ」と「整合させろ」は、除外宣言が無いと両立しない。 雛形が配る例示データは、実案件が絶対に使わない番号帯に隔離する。

改善 ③7 / 10
改善 ④ — 自分の修正が次の欠陥を生む

後のステップが前のステップの判定を壊していた

原因

Step1 に「業務一覧の各行に区分を記入（空欄0件）」を足し、 別の周に Step5 へ「対象判断は 03-boundary が正本」を足した。 両方を素直に守ると 02-external の区分列が消え、 Step5 を実行した瞬間に Step1 の判定が × に変わる。

実行者からは「どうやっても守れない」として報告された。

対処

「02-external の区分列は Step1 時点の暫定値なので、 消さずにそのまま残す（消すと Step1 の判定が後から × になる）」と明記。 正本は 03-boundary のまま。

効果

6周目の実行者が「Step5 で消しかけたが、この一文で止めた」と報告。 最終状態でも Step1 の判定は ○ を維持。

一般化：ステップ別の判定を足したら、フェーズ終了時点でもその判定が真かを確かめる。 各ステップ単体では全部 ○ でも、通しで見ると後段が前段を壊していることがある。

改善 ④8 / 10
改善 ⑤ — 指示の書き方そのもの

実測で「嘘」を止めた4つの書き方

ゴールは「状態」で書く。作業で書かない

「UC を洗い出す」は終わりが判定できない。 「アクターの紐づかない UC が 0 件」なら判定できる。 判定を数で書くと自己採点に解釈の余地が消える。

禁止は名指しで書く

「思いつかない状態を無理に捻り出さない」 「遷移は書かない」といった具体的な一文が最も強く創作を止めた。 実行者は「これが無ければ確実に創作していた」と明言。抽象的な注意書きは効かない。

入力に無い情報を事実として書かせない

「ブリーフに無いことは未確定として扱う」だけで、 貸出期間・延滞料金といった一般知識による創作がほぼ全部止まり、仮定・未決へ逃げた。

途中段階で機械検査の全通過を求めない

欠落があって正常な段階に整合を要求すると、 AI は空欄をもっともらしい嘘で埋める。 「 ERROR が出てもこのフェーズでは修正しなくてよい」と書き、--step で機械化した。
